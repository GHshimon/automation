## 1. 目的

いまは、オーナーがチャットで指示したときだけAIが動く。これを次の形に変える。

> 決まった時刻に収集プログラムが状態を集める。オーナーは横断ダッシュボードを見て、オーケストレーターAIと短く会話する。AIは根拠付きの提案と作業カードの下書きを出し、オーナーは承認・却下・保留を選ぶだけでよい。元に戻せる作業は隔離した環境で、AI同士（Codex と Claude）が実装・レビューする。外に影響する操作は、AIからは実行できない。

**原則**: 安全と費用の境界は、AIの判断ではなく、普通のプログラムと OS の権限で強制する。AIは「提案する側」であり、「止める側」や「許可する側」にはしない。

```

        ▼
```

## 4. 強制の仕組み（v0.2 の中心）

### 4.1 収集の失敗と「差分なし」を区別する

state には次の項目を必ず持たせる。

- `collection_status`: `complete` / `partial` / `error`
- 対象件数（前回との増減）、最終成功時刻、処理時間、設定ハッシュ
- コマンドごとの失敗理由

**AIを起動しない（静かに終わる）のは、`complete` かつ前回と同じ範囲かつ意味のある差分がないときだけ**。`partial` と `error`、対象件数の減少は、それ自体を異常として通知する。差分とは別に、時刻で判定する項目も持つ（承認待ちの滞留時間、長期の停滞、期限の超過）。

### 4.2 費用の上限で実際に止める

- **実行前に予算を確保する**: AIを起動する前に、見込み額を ledger から差し引いて確保する（同時実行に備えて排他ロック）。確保できなければ起動しない。
- **プロセスに上限を課す**: 最大ターン数・実行時間・再試行回数を引数で固定する。超えたらラッパーが強制終了する。
- **実行後に精算する**: `--output-format json` の実費とトークン数で確保額を精算し、ledger に記録する。
- 上限（仮決定）: 全体 **$0.50/日**、1プロジェクト **$0.15/日**。80%で警告、100%で停止して通知。
- **結論を先に書かせる**: 途中で止まっても成果が残るようにする（Codex の初回レビューは利用枠が尽きて回答ゼロだった）。

### 4.3 L0〜L3 をルールで強制する

レベルは、AIの分類ではなく、プログラムの許可リストで決める。AIの提案に付いたレベルは参考表示にとどめる。

| レベル | 使えるツール・権限 | 書き込み先 | ネットワーク |
|---|---|---|---|
| L0 観測 | 収集プログラムだけ（AIなし） | ops-pulse の data のみ | 決めた照会先だけ（gh など） |
| L1 提案 | Read/Glob/Grep、構造化出力 | 承認箱のドラフトだけ（プログラムが書く） | なし |
| L2 元に戻せる作業 | 上記＋編集。**隔離 worktree の中だけ** | その worktree の作業ブランチ | なし（調査は §6 に分ける） |
| L3 外に出る・元に戻せない | **AIから到達できる実行経路を作らない** | — | — |

「元に戻せる」は「安全」と同じではない。L2 でも push・外部送信・認証情報への到達はできないようにする。

### 4.4 state に版と鮮度を付ける

state のすべての項目に `schema_version`・収集時刻・生成元（どの収集器か）・範囲を付ける。古い state に基づく提案は、承認時の再判定で却下する。

## 5. オーケストレーター会話

- **ProjectPilot の会話入口をそのまま広げない。** 既存の入口は「1つのプロジェクト内」を前提にしている。同じやり方（許可した資料だけを一時cwdに置く、全文は保存しない、記録はオーナーが確認した Capture だけ）を使う**別のアダプター**を作る。
- 持たせるもの: 正規化済み state の読み取り、根拠付きの提案、提案ドラフトの作成、費用・鮮度・収集失敗の表示。
- 持たせないもの: シェル実行、リポジトリへの書き込み、外部送信、認証情報、カードの承認、レベルの最終決定。
- **起票は期限付きのドラフト**にする（例: 7日で失効）。同じ対象・同じ内容のドラフトはまとめる。カードを作りすぎると、オーナーの負担と誤った実行の誘因になるため。
- 一時cwdに資料をコピーするときは実体化する（シンボリックリンクは追わない）。拡張子・容量・パスは許可リストで制限する。資料の中の文章は命令として扱わない。
- 会話の全文は残さない。ただし監査用に、入力ファイルの一覧とハッシュ、state の版、モデル、出力のハッシュ、承認された Capture は残す。
- Owner Gate は「承認したものと同じものが反映される」ことを守るが、提案の正しさまでは保証しない。承認の直前に、対象・差分・state の鮮度・レベルを再判定する。
- 長期の記憶は会話ではなく、decisions・作業カード・state に置く。Vector DB は使わない。

## 6. リサーチの流れ（Web 検索を使う調査と技術開拓）

運用ループとは分ける。運用ループは自分のファイルを差分で読む。リサーチは信頼できない Web を、問いをきっかけに読む。

```
① 調査 research  WebSearch/WebFetch だけ。書き込み・実行・プロジェクトのファイルは不可
                 → 調査メモ（結論を先に、出典URL・確認日・確度）を AI-OS-wiki へ
     ↓ オーナーが「試す」を選ぶ
② 試作 spike     Web不可・隔離 worktree（L2）→ 小さな動作確認と計測
     ↓ Codex ⇄ Claude でレビュー
③ 判断           オーナーが採否 → decisions.jsonl ／ Harness配布パッケージ ／ wiki
```

- きっかけ: オーナーの質問、オーケストレーターの提案（リサーチカード）、週1回の技術動向の見回り。
- 使い分け: 速報とXの動向は Grok、深掘りは Perplexity、公式ドキュメントと自分の環境との照合は Claude、反対の立場からの検証は Codex。重要な問いは2系統で調べ、食い違う点だけをオーナーに見せる。
- 上限: 1件あたり Claude で $1、検索は最大10回、読むページは最大5件。浅く調べて結論が出なかったときだけ深掘りする。§4.2 の予算確保を共用する。
- 運用ループの判断AIには、Web の本文ではなく調査メモへのリンクだけを渡す。

## 7. 決定事項（仮決定。v0.2 の承認時に decisions へ記録）

1. 通知先: **Gmail の自分宛て**。本文には機密を書かず、詳細は tailnet で見る。launchd からの送信用の認証設定は、オーナーが行う。
2. 費用の上限: **全体 $0.50/日、1プロジェクト $0.15/日**。80%で警告、超過で強制停止。
3. 配置: **`automation/`**。Mac環境は収集の対象であり、制御する側にはしない。
4. ProjectPilot への登録: **作業が発生したプロジェクトから順に**。30件の一括登録はしない。
